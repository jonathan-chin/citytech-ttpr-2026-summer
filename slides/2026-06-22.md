# What Is a Database?

A **database** stores data **permanently**, so it survives even after your program or server stops.

- Memory (**RAM**) is **volatile**: it is wiped on restart. Disk is **non-volatile**: it persists
- The **Express servers** you built last week kept data in RAM, so it was lost on every server **restart**
- A database keeps your data on disk, and lets you **store, search, update, and relate** lots of it efficiently
- Most apps rely on one **to provide** features like accounts, posts, orders, and messages

# Term: Schema

A **schema** is the **structure** of your data: the tables, their columns, and each column's type.

```sql
CREATE TABLE students (
  id     INTEGER PRIMARY KEY,
  name   TEXT,
  major  TEXT
);
```

It is the **blueprint**; the rows are the data that fills it in.

# SQL

**SQL** (Structured Query Language) is how you talk to a relational database.

- You write **queries** to create, read, update, and delete data (**CRUD**)
- Reminder: **CRUD** = **C**reate, **R**ead, **U**pdate, **D**elete, the four basic data operations
- It's **declarative**: you describe *what* you want, and the database works out *how* to get it

---

# Term: Query

A **query** is a request to the database, written in SQL.

```sql
SELECT name, major FROM students WHERE major = 'CS';
```

Returns:

  <tr><th>name</th><th>major</th></tr>
  <tr><td>Ada</td><td>CS</td></tr>
  <tr><td>Linus</td><td>CS</td></tr>
</table>

# Common SQL Commands

The four CRUD operations map to four SQL keywords:

```sql
SELECT name FROM students;
INSERT INTO students (name) VALUES ('Ada');
UPDATE students SET major = 'Math' WHERE id = 2;
DELETE FROM students WHERE id = 3;
```

- **SELECT** = Read, **INSERT** = Create, **UPDATE** = Update, **DELETE** = Delete

---

# The Structure of a Query

Like any SQL statement, a query is a **verb** plus a set of **clauses**.

```sql
SELECT name, major   -- verb: the action (here, read these columns)
FROM students        -- clause: which table
WHERE major = 'CS'   -- clause: which rows
ORDER BY name;       -- clause: how to sort
```

- It opens with a **verb**: `SELECT`, `INSERT`, `UPDATE`, or `DELETE`
- Then come **clauses**, each introduced by a **keyword** like `FROM`, `WHERE`, or `ORDER BY`
- Clauses follow a set order, and the statement ends with a semicolon `;`

---

# Required and Optional Clauses

Some clauses are **required**, others are **optional**.

- **SELECT** and **FROM** are the core: say *what* to read and *where* from
- **WHERE**, **ORDER BY**, `LIMIT`, etc are **optional**: add them only when needed
- **Order matters** Clauses must appear in a fixed sequence (`SELECT`, then `FROM`, then `WHERE`, then `ORDER BY`), or it is a syntax error

---

# More on SQL

SQL is a **standard language**, so the same core skills work across many databases.

- **Learn it once**: your skills transfer across most relational databases
- Expect small **dialect** differences from one database to another

# Flavors of SQL

Different databases implement SQL with small **dialect** differences:

- **PostgreSQL**: powerful, open-source, standards-focused; a great default (installed in Week 1)
- **SQLite**: a tiny, file-based database; zero setup, ideal for small apps and learning
- **MySQL / MariaDB**: very common in web stacks
- **Big vendors** offer their own: **SQL Server** (Microsoft) and **Aurora / RDS** (AWS)

The **core SQL** is the same; details like data types and extra features vary.

# Relational Databases

The databases we've used are **relational**: data lives in **tables** that **relate** to each other.

- Each table holds one kind of thing (`games`, `studios`)
- Tables link through shared values: a game's `studio_id` points to a row in `studios`
- This avoids repeating data and keeps it consistent
- You query them with **SQL**

---

# Relational vs Non-Relational

Not every database is relational. **Non-relational** ("NoSQL") databases store data as documents, key-value pairs, or graphs.

|  | Relational (SQL) | Non-Relational (NoSQL) |
|---|---|---|
| Structure | tables with a fixed schema | flexible documents / key-value |
| Strengths | consistency, relationships, rich queries | scale, flexibility, fast simple reads |
| Examples | PostgreSQL, SQLite, MySQL | MongoDB, Redis, DynamoDB |

We focus on **relational** databases. Non-relational is **out of scope** for this program.

# Join

A **join** combines rows from two tables using their key relationship.

```sql
SELECT games.title, studios.name
FROM games JOIN studios
ON games.studio_id = studios.id;
```
